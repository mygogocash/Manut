## Conventions + pitfalls (read before committing)

These bit me multiple times this session. Save yourself the cycle.

### `apps/web/tsconfig.tsbuildinfo` is tracked AND gitignored

- The file shows up in `git status` after every `pnpm type-check`.
- It's in `.gitignore` but was added to the index before the ignore landed.
- **Always `git checkout apps/web/tsconfig.tsbuildinfo` before `git add -A`** or it lands in your commit.
- Long-term fix: `git rm --cached apps/web/tsconfig.tsbuildinfo`. Not done this session because it would touch other in-flight PRs.

### `pnpm lint` is broken in CI

- ESLint config `@nexora/eslint-config` is missing. Lint exits with `Cannot find package`.
- `pnpm type-check` + `pnpm test` are the working verification commands.
- The PR Checks workflow may still attempt lint — last few PRs landed without lint passing because the brand-drift / type-check / test gates carried.

### Express route order

- Literal paths MUST register before `:param` routes or Express matches the param first.
- This session: `POST /partners/reorder` had to land before `GET /partners/:id`; `POST /partners/:id/ensure-workspace` is fine because the literal segment is the third path component.
- Check `apps/api/src/modules/projects/projects.controller.ts` for the canonical pattern.

### Prisma migrations against the shadow DB

- `pnpm db:migrate` fails locally with `P3006` on the pre-existing `20260518000100_amount_band_routing` migration (shadow DB can't apply it cleanly).
- **Don't run `prisma migrate dev` against the prod URL** — that's destructive.
- Trust the CI pipeline: it runs `prisma migrate deploy` (no shadow check) before the Docker build.
- All migrations should be idempotent (`IF NOT EXISTS`) so half-applied rollouts can be re-run safely. Examples this session: `20260802000000_partner_projects_layout`, `20260803000000_partner_primary_project`.

### Radix Select race with async-loaded options

- When `value` is set before the matching `<SelectItem>` mounts, Radix can render the placeholder permanently.
- Pattern: `<Select key={`mgr-${items.length}`} value={...}>` — remount on item-count change so Radix re-evaluates.
- Also: merge the bound option into the candidate list when async fetch might exclude it (inactive user, past page cap).
- Used in: employee form Line Manager (#574), partner form Owner picker (#574).

### Combining PRs

- Project convention: when you have multiple small PRs ready, bundle them into one with `chore: combine #X + #Y — short summary`.
- Create a fresh branch from `main`, cherry-pick the commits, push, open the combined PR, close the originals with "Superseded by #Z".
- Delete the source branches on remote: `git push origin --delete <branch1> <branch2>`.

### Commit messages

- Conventional commits: `feat(scope):`, `fix(scope):`, `chore(scope):`, `refactor(scope):`.
- Multi-line body explaining the *why*. Co-author footer:
  ```
  Co-Authored-By: Claude Opus 4.7 (1M context) <noreply@anthropic.com>
  ```
- Pass via HEREDOC to preserve formatting:
  ```
  git commit -m "$(cat <<'EOF'
  fix(scope): short subject

  Body paragraph explaining the why.

  Co-Authored-By: Claude Opus 4.7 (1M context) <noreply@anthropic.com>
  EOF
  )"
  ```

### Branch naming

- AI-authored: `claude/<short-slug>`.
- Other: `feat/<slug>`, `fix/<slug>`.

### Permissions system

- Defined in `apps/api/src/common/constants/permissions.ts` as `PERMISSION_DEFINITIONS` (array of `{ code, module, action, description }`).
- The `PERMISSIONS` const auto-derives keys: `it-crm:read` becomes `PERMISSIONS.IT_CRM_READ` (dashes + colons → underscores, uppercased).
- The type block below the reduce MUST be kept in sync — TypeScript will not infer it from the array.
- Admins (system role `Admin`, `isSystem=true`) auto-grant every code via `auth.service.ts` line ~103. So adding a new perm works immediately for admins without seed updates.
- For non-admin roles: HR configures via `/roles` UI. Don't backfill via seed unless explicitly asked.

## Module quick-reference

### Backend (`apps/api`)

- Modules under `src/modules/<name>/` with `<name>.controller.ts`, `<name>.service.ts`, `<name>.repository.ts`, `<name>.validation.ts`.
- Routes register on the bottom `Router()`. Literal paths before `:param`.
- Validate with Zod schemas in `<name>.validation.ts`.
- Errors: `BadRequestException`, `NotFoundException`, `ForbiddenException`, `ConflictException` from `@/common/exceptions/http-exception`.
- Logger: pino. `logger.info("message", { context })` — string first, object second. Don't pass object first.
- Permissions: `requirePermission(PERMISSIONS.X, PERMISSIONS.Y)` — ANY of the listed codes admits the caller.

### Frontend (`apps/web`)

- App Router under `src/app/(dashboard)/<module>/`.
- Components under `src/components/<module>/`.
- Services under `src/services/<module>.service.ts` — calls `api.get/post/put/delete`.
- Forms: react-hook-form + zod + shadcn `Form` primitives.
- Auth state: `useAuth()` exposes `user`, `roles`, `permissions`, `hasPermission`, `hasAnyPermission`, `hasRole`, `refreshUser`.
- Permission gating: `<PermissionButton permission="x:y">` / `<PermissionDropdownMenuItem permission="x:y">`.
- DataTable: `@/components/shared/data-table` supports `onRowClick`, `pagination` slot.

### Database (`packages/database`)

- Schemas split across `prisma/schema/*.prisma` by domain (core, operations, hr, performance, sales-crm, etc.).
- `pnpm db:generate` regenerates the Prisma client after schema edits.
- Migration files in `prisma/migrations/YYYYMMDDHHMMSS_slug/migration.sql`.
- Idempotent SQL preferred. Use `IF NOT EXISTS` / `IF EXISTS`.
- Production migrations apply automatically via the GitHub Actions `Apply Prisma migrations to prod DB` step (runs `prisma migrate deploy` before the Docker build).

### New pitfalls

- **`Intl.supportedValuesOf("region")` is not a valid key** — only `calendar`, `collation`, `currency`, `numberingSystem`, `timeZone`, `unit`. Use `Intl.DisplayNames({ type: "region" })` with a hardcoded ISO list instead (see `apps/web/src/constants/crm-geo.ts`).
- **`listDirectorySchema.limit` was capped at 100** (raised to 500 in #596). Any new caller that wants a larger page must check the cap before sending — Zod returns 422 with a generic "Validation failed" body, and the frontend's `try/catch` typically swallows it into an empty array.
- **Socket.io has its own CORS handler** in `messages.socket.ts`. Make sure any new env-var-driven origin list mirrors what Express CORS reads — the two diverged in prod and silently broke realtime (#599 fixed).
- **`User.department` does not match `PROJECT_DEPARTMENT_VALUES` reliably** in prod. Don't gate UI on the assumption that an employee in the IT team has `department === "IT"`. Use `/directory/assignable` without the filter, OR clean up the User.department taxonomy first.
- **`req.user.id` from `resolveAuthUserFromToken` is the Prisma User.id which equals the Supabase auth uid**. Don't translate — they share UUIDs by design.
