## Magic-link rollout state

Magic-link sign-in (originally landed in #473) is **fully hidden**
right now. Three layers:

1. `/magic-link` page (`apps/web/src/app/magic-link/page.tsx`) does
   `redirect("/sign-in")` server-side.
2. The sign-in form (`apps/web/src/components/auth/login-form.tsx`)
   doesn't render an "Email sign-in link" button.
3. Backend gates the request on
   `MAGIC_LINK_ALLOWED_ROLES` env var.
   Default is empty (`""`) → no role passes → only the system Admin
   role bypasses (via the existing `Admin` implicit-everything path).

   exist (`packages/database/prisma/seed.ts` doesn't ship it as a
   system role).

3. Set Cloud Run env:
   ```
   gcloud run services update nexora-api \
     --region=asia-southeast1 --project=tbh-nexora \
     --update-env-vars='MAGIC_LINK_ALLOWED_ROLES=IT'
   ```
4. Revert (or partially revert) these two hunks from #499:
   - `apps/web/src/app/magic-link/page.tsx` — restore the original
     `MagicLinkPage` (git history has the previous form impl).
   - `apps/web/src/components/auth/login-form.tsx` — re-add the
     "Email sign-in link" button.

Forgot-password flow is **not** gated — every active user can still

## Coding-rules quick reminders

If you haven't read `CLAUDE.md` recently, the highlights that bit
people in this session were:

- **Express route ordering**: literal paths (`/settings`, `/options`)
  must register before `/:id`. Got bitten when adding the new CRM
  settings module.
- **Migrations must be idempotent**. `IF NOT EXISTS` on table /
  constraint creation, seed via `INSERT … WHERE NOT EXISTS`. Both new
  migrations this session (`20260711000000_helpdesk_settings`,
  `20260714000000_ninety_day_receipt`, `20260721000000_crm_settings`)
  follow this pattern; mirror them for any new singleton-settings
  table.
- **Prisma format reflows every schema file**. When editing a single
  `*.prisma`, `pnpm db:generate` is safe; `pnpm db:format` rewrites
  whitespace across the whole `schema/` dir. Prefer surgical
  `cat >> file` appends for new models so the PR diff stays
  reviewable.
- **`Date#toISOString().slice(0, 10)` is wrong for local-day values**.
  Browsers east of UTC shift forward; west shift backward. Use a
  local-component formatter (`ymdLocal` pattern from #501,
  `format-currency` style).
- **#509 / `combined/*` PR pattern**: when bundling someone else's
  branches that predate recently-merged work in main, the auto-merge
  can silently drop features (it happened with #500's sales-page
  notification button when folding #505). After every combined merge,
  diff the resulting branch against main and against each input PR's
  intent — restore any missing hunks manually before pushing.
